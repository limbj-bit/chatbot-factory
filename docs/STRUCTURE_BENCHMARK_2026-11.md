## 0. 한 장 요약

**우리는 이미 "Cafe24 뷰티 + 신선식품 버티컬 AI CS 에이전트"라는 희소한 자산을 갖고 있다.**
성분·피부고민 기반 RAG, 상품 카드, Cafe24 OAuth 주문 조회, 사진 기반 클레임 판정, 환불 정책 엔진, AS 시나리오 상태머신이 한 코드베이스에 있다. 경쟁사(Channel Talk ALF, Gorgias, Intercom Fin, Zendesk, Tidio)는 모두 **수평형 helpdesk + AI agent**이며, 이 조합을 기본 제공하지 않는다.

**특히 신선식품/과일은 코드에 이미 1등 시민으로 들어가 있다.**
`fresh_food` 업종 팩에 전용 페르소나("신선식품 전문 상담사"), 전용 비전 프롬프트(곰팡이·부패·눌림·파손·변색·과숙), 48시간 품질보상 정책(전액 30% / 부분 10% / 접수 2일)이 구현되어 있다. 신선식품은 "새로 만들 기능"이 아니라 **이미 있는 기능을 상품화하면 되는 첫 wedge**다.

**그러나 지금은 "상용"이 아니라 "데모에 가까운 상태"다.**
1. 라이브는 자동 배포가 꺼져 있어 2026-11-01 빌드(`120350f`)에 4일간 멈춰 있었다. Manual Deploy 후 `e56cfb8`로 갱신했고 `/health`·`/health/ai`·schema-status는 정상화됐다. 그러나 **auto-deploy는 여전히 Off**라 다음 수정도 수동 배포가 필요하다.
2. 사람 인계가 읽기 전용 알림 목록이라 실제 운영이 불가능하다.
3. 주문 조회 외에 취소·교환·환불 실행 액션이 없다.
4. 분석/QA/평가 지표가 없어 고객사가 ROI를 증명할 수 없다.
5. Render Free 콜드스타트(**실측 26.3초**)와 무료 LLM 의존이 "ChatGPT 수준" 약속을 깨뜨린다.
6. 라이브 카드가 **0개**로 나왔다. 원인은 카드 필터가 대화형 토큰을 상품명으로 오인한 것이며, `af9e7db`에서 수정했다(배포 대기). 텍스트 추천 자체는 실제 카탈로그 상품과 일치했다.
7. 신선식품 클레임 팩은 코드에 있지만, 라이브 스토어에서 사진 판정·부분환불 시나리오를 검증한 적이 없다.

**전략은 하나다. 수평형 helpdesk와 정면 승부하지 말고, "신선식품 클레임"과 "뷰티 상담" 두 개의 버티컬 팩으로 이긴다.**
신선식품은 사진 한 장으로 변질·파손을 판정해 환불/재배송을 끝내는 **ROI wedge**, 뷰티는 성분 상담으로 카드 클릭·객단가를 올리는 **expansion pack**이다.
가격은 경쟁사의 종량제(대화당 ₩500~2,900)를 따라가지 말고, **신선식품 월 정액 ₩99k~₩199k, 뷰티 ₩199k~₩299k + 공정사용**으로 3~10배 저렴하게 포지셔닝한다.

| 필요한 지식 | 산지·품종·제철·후숙·보관·중량/등급 | 성분·피부타입·효능·사용법 |

| 정책 | 48시간, 사진 필수, 부분/전액 환불, 재배송 우선 | 개봉/씰, 트러블, 교환 |

### 1.2 REA가 증명한 것

1. **고객 접점은 "서버 렌더링 HTML 1장 + 생성형 위젯 스크립트 1개"다.**
   SPA도, 번들러도, 클라이언트 라우터도 없다. 설치가 `<script src=".../api/widget/script?mall_id=...">` 한 줄이라는 뜻이며, 이는 중소 스토어 온보딩에서 강력한 장점이다.
2. **DOM이 113노드로 매우 가볍다.**
   초기 로딩과 TTFB에 유리하다. 반면 가상화 리스트, 복잡한 카드 인터랙션, 상태 관리가 없다는 뜻이기도 하다.
3. **정적 분석으로는 API 호출이 보이지 않는다.**
   위젯이 `config.apiBase + "/api/chat/stream"` 같은 **동적 문자열 조합**으로 호출하기 때문이다. REA가 endpoints 0개를 반환한 것은 "API가 없다"가 아니라 "정적 추출이 불가능하다"는 뜻이다.
4. **세션 지속은 localStorage 기반이다.**
   쿠키가 아니라 `claim_chat_session_{mallId}` 키를 첫 상호작용 때 만든다. 개인정보 측면에서는 가볍지만, 브라우저/기기 간 연속성은 없다.

- 런타임 API 호출, 서버 내부, DB, LLM 라우팅은 REA의 정적 캡처 범위 밖이다.

### 2.5.1 신선식품 팩: 이미 구현된 것 (Observed)

신선식품은 "추가로 만들어야 할 업종"이 아니라, **이미 코드에 들어가 있는 첫 번째 상품 후보**다. 소스에서 확인된 것은 다음과 같다.

| 스토어 프리셋 | `app/application/store_service.py` | 봇 이름 "신선봇", 정책 문구 "48시간 100% 품질보상제", 전액환불 30% / 부분환불 10% / 접수 2일 |

| 결정형 FAQ | `app/infrastructure/rag/engine.py` | 단순 변심 반품 불가, 48시간 이내 사진 접수, 재배송/환불 안내 |
| 클레임 파이프 | `app/application/claim_service.py` | 이미지 검증 → 중복 해시 → 비전 관측 → 정책 엔진 → 전액/부분 환불/재검수/수동검토 |

**즉, 신선식품 출시에 필요한 "도메인 팩"은 이미 있다.** 없는 것은 ① 라이브 검증 ② 상품 카탈로그 정합성 ③ 환불 *실행* ④ 골든셋이다. 이 넷은 업종과 무관한 **공통 상용화 과제**이므로, 신선식품을 먼저 팔아도 로드맵이 갈라지지 않는다.

**신선식품 고유의 위험 (Inferred)**
- **오탐 비용이 비대칭이다.** 정상 상품을 변질로 오판하면 환불 누수, 변질을 정상으로 오판하면 재구매 상실 + 리뷰 타격. 뷰티보다 임계값 민감도가 높다.
- **사진 품질 의존.** 조명/각도/포장 상태에 따라 같은 상품도 다르게 보인다. "정상/경미/심각" 3단계 라벨셋이 필수다.
- **정책이 계절·품목별로 다르다.** 딸기/복숭아/포도/한라봉은 후숙·변질 속도가 다르다. 단일 48시간 규칙은 시작점일 뿐이다.
- **식품안전 경계.** 곰팡이·이물·식중독 의심은 AI 단독 판정 금지, 즉시 사람 인계. 이 가드는 코드에 있으나 라이브 검증이 없다.

### 2.6 데이터 모델 (15 테이블)

- 멀티테넌시는 `mall_id` 스코프로 구현되어 있다.

### 3.2 상태 엔드포인트가 거짓말을 한다 → **수정·배포 확인** (P0)

`/health` (이전, `120350f`):
```json
{"status":"healthy","mock_ai":true,"mock_cafe24":true,"deploy_marker":"schema-heal-v2"}
```
- 실제 스트리밍은 LLM이 생성한 한국어 답변을 반환했다. `mock_ai: true`는 **설정값(`settings.MOCK_AI`)** 을 읽은 것이고, 실제 라우터의 유효 모드가 아니다.
- **수정·배포 확인(`e56cfb8`)**: `/health`가 라우터의 `effective_mock_mode`(`mock_ai:false`), `live_provider_count:3`, `ai_provider_order:["groq","nvidia","openrouter"]`, `git_commit:e56cfb8…`를 반환한다. `configured_mock_ai:true`는 프로덕션 환경변수 값이며 실제 모드가 아니다.
- `/health/ai`도 200으로 복구됐다. `vision_order:["nvidia","openrouter"]`, 쿨다운/지연 EMA 포함.

`/api/system/schema-status` (이전, `120350f`):
```json
{"ok":true,"stores_columns":null,
 "probe_error":"DBAPIError: ... current transaction is aborted ..."}
```
- `ok: true`인데 컬럼 목록은 `null`이다.
- PostgreSQL에서 한 문장이 실패하면 트랜잭션이 aborted 상태가 되고, 이후 조회가 모두 무시된다.
- **수정·배포 확인(`e56cfb8`)**: `dialect:postgresql`, `ok:true`, `stores_columns` 32개(`brand_logo_url` 포함), `probe_error` 없음.
- 상용 모니터링에서 이 엔드포인트를 health check로 쓰기 전에, 배포 후 실제 컬럼 목록이 반환되는지 주기적으로 확인해야 한다.

### 3.7 신선식품 라이브 검증 공백 (P0)

신선식품 팩은 코드에 있지만, **실제 신선식품 스토어에서 한 번도 끝까지 돌려본 적이 없다.** 이 공백은 "기능이 없다"보다 위험하다. 있다고 말했는데 틀리면 신뢰가 한 번에 깨진다.

| 시나리오 | 코드상 기대 동작 | 라이브 검증 |
|---|---|---|
| 배송 중 변질(곰팡이) | 비전 `mold`/`rot` → 손상 비율 → 전액 환불 또는 재배송 | **미검증** |
| 눌림·파손(딸기/복숭아) | `bruise`/`crush_damage` → 부분 환불 10~30% | **미검증** |
| 과숙/미숙 | `overripe`/`underrripe` 판정 → 재배송 우선 | **미검증** |
| 중량 부족 | 사진만으로 판정 불가 → 사람 인계 | **미검증** |
| 오배송/누락 | `wrong_item`/`missing_parts` → 재배송 | **미검증** |
| 배송 지연 후 변질 | 48시간 정책 + 지연 책임 → 전액 환불 | **미검증** |
| 정상 상품 | 환불 거절 + 보관/후숙 안내 | **미검증** |
| 곰팡이/이물/식중독 의심 | AI 단독 판정 금지, 즉시 인계 | **미검증** |

**특히 위험한 것**: 마지막 두 줄. 정상 상품을 환불해주는 오탐은 **환불 누수**로 직결되고, 식중독 의심을 AI가 "경미"로 판정하면 **법적/브랜드 리스크**가 된다. 이 둘은 데모가 아니라 골든셋으로 증명해야 한다.

**라이브 검증 방법 (권고)**
1. 신선식품 테스트 스토어 1개 생성(`fresh_food` 업종).
2. 정상/경미/심각 3단계 × 6개 품목 = 18장의 라벨된 사진을 준비.
3. 각 사진에 대해 비전 코드, 손상 비율, 정책 결정, 고객 안내 문구를 기록.
4. 오탐(정상→환불) 0건, 미탐(심각→정상) 0건이 될 때까지 임계값 조정.
5. 결과를 `docs/FRESH_CLAIM_GOLDENSET.md`로 남겨 영업 자료로도 사용.

- 뷰티는 성분 상담·비교·추천으로 **턴 수와 컨텍스트가 길다.** 같은 정액에 넣으면 원가가 더 든다.
- 따라서 신선식품은 **진입 가격(₩99k)**, 뷰티는 **가치 가격(₩199k~)** 으로 나누는 것이 합리적이다. 두 가격 모두 ALF/Gorgias/Fin 대비 3~10배 저렴하다.

**해석**
- ALF는 국내 기준 가장 현실적인 비교군이다. 플랫폼 ₩200k + 대화당 ₩700이므로, 1,000건이면 월 ₩900k다. **신선식품 스토어에게 ALF는 월 매출의 상당 부분을 CS에 쓰는 선택**이 된다.
- Gorgias는 AI 해결과 티켓을 별도 미터로 과금한다. 3rd-party 분석에 따르면 AI 해결 1건이 티켓으로도 집계돼 이중 청구가 발생한다. 고객사가 체감하는 "AI가 해결할수록 비싸지는" 구조다.
- Fin은 $0.99/outcome으로 단순하지만, 1,000건이면 월 ₩1.5M 수준이다.
- 우리가 ₩99k~299k 정액을 유지하려면, 대화당 원가를 **₩100 이하**로 눌러야 한다. 무료 티어 의존은 원가를 숨기지만, 유료 전환 시 Groq/NVIDIA 단가와 캐시 히트율로 결정된다. **정액제는 원가 가시성 없이 출시하면 역마진 위험**이 있다.

**Channel Talk ALF**

**Intercom Fin**
- 강점: 평균 76% 해결률, 12,000+ 고객, Procedures(읽기/쓰기), 옴니채널, 테스트/QA/Insights, 99.8% SLA, SOC2/ISO 42001.

### 4.5 신선식품 심층: 왜 이 시장이 먼저인가 (Inferred + Recommendation)

**시장 구조**
- 국내 신선식품 온라인 구매는 정기배송·새벽배송·산지직송으로 확대됐고, **클레임의 대부분이 "사진 1장"으로 시작**된다.
- 소상공인/중소 신선몰은 CS 인력이 1~2명이다. 변질 사진을 보고 환불/재배송을 판단하는 일이 하루 수십 건 발생한다.
- 이들은 Gorgias/Fin을 도입할 예산도, 운영 인력도 없다. **월 ₩99k + 위젯 1줄**이 현실적인 진입점이다.

**경제성 (가정 기반 추정)**
- 신선몰 월 주문 3,000건, CS 문의 10% = 300건, 그중 클레임 30% = 90건.
- 클레임 1건 처리 10분 × 90건 = 월 15시간. 시급 ₩15,000이면 월 ₩225k의 인건비.
- 환불 누수(정상 상품 오환불) 5% × 평균 환불 ₩30,000 × 90건 = 월 ₩135k.
- **우리 가격 ₩99k~₩199k는 "인건비 + 누수"만으로도 정당화된다.** 뷰티는 여기에 매출 기여(카드 클릭/객단가)를 더해야 정당화된다.

**신선식품에서 이기려면 반드시 필요한 것**
1. **3단계 판정**: 정상 / 경미(부분환불) / 심각(전액환불·재배송). 애매하면 사람 인계.
2. **품목별 정책**: 딸기·복숭아·포도·한라봉 등 부패 속도가 다른 품목은 임계값을 다르게.
3. **재배송 우선**: 환불보다 재배송이 재구매율에 유리한 경우가 많다. 정책 엔진에 "재배송 우선" 규칙 필요.
4. **사진 가이드**: 고객에게 "상품 전체 + 문제 부위 + 포장 상태" 3장을 요청하는 UX. 판정 정확도를 올리는 가장 싼 방법.
5. **식품안전 가드**: 곰팡이/이물/식중독 의심은 AI 판정 중단, 사람 즉시 인계.
6. **신선식품 카탈로그 정합성**: 산지·품종·중량·등급·유통기한이 상품명/상세에 일관되게 있어야 상담이 가능하다.

**신선식품에서 지면 안 되는 것**
- "사진을 봤는데 정상입니다"라고 말하고 실제로는 변질된 경우. 이 한 번으로 브랜드가 끝난다.
- 중량 부족/오배송처럼 사진으로 판정 불가한 것을 AI가 억지로 판정하는 것.
- 배송 지연과 변질의 책임 경계를 AI가 임의로 나누는 것.

## 5. 벤치마킹 포인트: 무엇을 베끼고, 무엇을 피하고, 어디서 이길까

### 5.1 베낄 것 (Copy)

1. **Outcome/usage pricing의 투명성**
   - Fin: $0.99/outcome, ALF: ₩500~700/대화.
   - 우리도 "정액 + 초과분 단가"를 공개하라. 숨은 미터는 신뢰를 깎는다.
   - **신선식품/뷰티 두 플랜의 초과 단가를 각각 명시**해, 업종별 원가 차이를 가격에 반영하라.
2. **Actions / Procedures**
   - Fin Procedures, ALF 커맨드, Gorgias 주문 액션.
   - 우리는 "주문 조회 → 취소/교환/환불 → 배송 추적 → 쿠폰" 순으로 액션을 늘린다.
   - **신선식품은 "재배송 생성"을 1순위 액션으로** 둔다. 환불보다 재구매율이 높다.
3. **사람 인계 + 문맥 전달**
   - 모든 경쟁사가 인박스/SLA/배정을 갖고 있다.
   - 우리는 최소 viable 인박스(스레드, 답장, 배정, 상태, SLA)를 P1에 넣는다.
   - **신선식품은 "식품안전 인계" 전용 큐**를 별도로 둔다(곰팡이/이물/식중독).
4. **QA / 평가 / 시뮬레이션**
   - Fin은 배포 전 시뮬레이션/회귀 테스트를 제공한다.
   - 우리는 100개 골든셋 + CI 회귀 + "환각 0" 게이트를 만든다.
   - **신선식품은 정상/경미/심각 3단계 사진 18장을 골든셋에 포함**한다.
5. **지식 개선 루프**
   - ALF는 상담 데이터로 도큐먼트 개선을 제안하고, Fin Operator는 지식 최신화를 자동화한다.
   - 우리는 "답변 실패/지식 갭" 로그 → 크롤 재수집 → 문서 개선 제안으로 연결한다.
   - **신선식품은 "품목별 정책/유통기한" 문서를 지식 갭 1순위**로 관리한다.
6. **채널 확장**
   - 한국은 카카오 상담톡/네이버 톡톡이 필수다. ALF가 이걸로 이긴다.
   - 웹 위젯만으로는 카페24 유입의 절반을 놓친다. **신선식품은 카카오 주문 알림과의 연동 가치가 특히 크다.**
7. **신뢰**
   - ISMS/ISO, SLA, 데이터 보관/삭제 정책. 중견 브랜드 영업의 전제조건.
   - **식품은 "사진/주문정보 보관 기간"을 명시**해야 안심하고 맡긴다.

### 5.2 피할 것 (Avoid)

1. **Gorgias식 이중 미터(3rd-party 분석)**: AI 해결이 티켓으로도 과금되면 "해결할수록 비싸다"는 인식이 생긴다. 우리는 단일 미터로 간다.
2. **Zendesk식 좌석+AR 복잡도**: SMB는 계산을 못 한다. 정액제가 무기다.
3. **수평형 기능 팽창**: Intercom/ALF를 기능 수로 이길 수 없다. 신선식품 클레임/뷰티 상담/카페24에 집중한다.
4. **성공을 벌하는 종량제**: 자동화가 잘될수록 고객 비용이 늘면 갱신율이 떨어진다. 공정사용 + 상한선이 낫다.
5. **무료 티어 의존을 가격에 반영하지 않는 것**: 원가가 숨은 정액제는 규모가 커질 때 역마진이 된다.
6. **신선식품을 "뷰티의 하위 기능"으로 취급하는 것**: 사진 판정·48시간 정책·재배송은 뷰티와 다른 제품 표면이 필요하다. 하나의 엔진, 별도 팩이 정답이다.
7. **AI 단독 식품안전 판정**: 곰팡이/이물/식중독 의심을 AI가 종결하면 안 된다. "판정 보조 + 사람 인계"가 원칙이다.
8. **사진 1장으로 모든 클레임을 처리하는 것**: 중량 부족/오배송/누락은 사진 판정 대상이 아니다. 주문 데이터와 대조해야 한다.

### 5.3 이길 곳 (Win)

1. **신선식품 사진 클레임의 완결성**: "사진 1장 → 손상도 판정 → 재배송/환불 결정 → 고객 안내". 경쟁사에 없는 루프이고, 고객의 아픔이 가장 직접적이다.
2. **신선식품 가격**: 월 ₩99k~₩199k. ALF/Gorgias/Fin 대비 3~10배 저렴하고, 소상공인도 계산 없이 도입할 수 있다.
3. **뷰티 상담의 정확도**: 성분 근거, 피부고민 확장, 상품명 환각 0, 카드 일치율 90%+.
4. **Cafe24 네이티브 온보딩**: OAuth 연결 5분, 상품 482개 자동 학습, 주문/클레임까지 한 곳.
5. **업종 팩 교체**: 신선식품으로 시작해 뷰티/패션/전자로 확장하는 한 엔진. 고객 획득 비용을 재사용한다.

## 8. 의사결정이 필요한 것

1. **인박스를 직접 만들 것인가, ALF/카카오에 인계할 것인가?**
   - 직접 만들면 데이터/UX 통제권이 생기지만 2~3주가 든다.
   - 연동하면 빨리 출시되지만 "AI가 해결하고 사람이 마무리"하는 경험이 분리된다.
   - 권고: **P1에서 lightweight 인박스 v1을 직접 만들고, 카카오/네이버는 어댑터로 붙인다.** 인박스는 CS SaaS의 심장이라 아웃소싱하면 락인이 약해진다.
2. **정액제 vs 종량제?**
   - 권고: **정액 + 공정사용 + 초과 단가**. 단, 원가 계측(토큰/프로바이더/대화)을 먼저 붙인다.
3. **무료 LLM을 계속 쓸 것인가?**
   - 파일럿까지는 가능. 유료 고객 계약에는 **SLA 가능한 프로바이더(유료 Groq/NVIDIA) + 폴백**을 명시해야 한다.
4. **업종 확장 순서: 신선식품 먼저, 뷰티 다음?**
   - 기존 결론("뷰티 외 확장 금지")을 **폐기**한다. 신선식품은 이미 코드에 팩이 있고, 클레임 ROI가 가장 빨리 숫자로 증명되는 시장이다.
   - 권고: **신선식품을 첫 wedge로 2~3개 파일럿** → 클레임 처리 시간/환불 누수/재구매율을 증명 → **같은 엔진에 뷰티 팩을 붙여 expansion**. 뷰티는 성분 상담/카드 전환이라는 다른 KPI로 판다.
   - 단, 두 버티컬을 동시에 영업하지 않는다. 영업 메시지가 흐려지고, 라이브 검증 부담이 두 배가 된다.
5. **신선식품을 별도 제품으로 분리할 것인가?**
   - 권고: **분리하지 않는다.** 하나의 엔진 + 업종 팩 + 업종별 가격/온보딩. 별도 제품은 코드/운영/지원 비용을 두 배로 만든다. 브랜드만 "신선식품 클레임 AI"로 앞세우고, 뷰티는 확장팩으로 설명한다.

## 9. 결론

- **구조적 자산은 충분하다.** 신선식품 클레임 팩(변질/곰팡이/눌림/파손/과숙), 뷰티 도메인 RAG, Cafe24 주문, 사진 클레임, 정책 엔진, AS 상태머신은 수평형 경쟁사가 쉽게 복제하지 못한다.
- **신선식품은 "새로 만들 기능"이 아니라 "이미 있는 기능의 상품화"다.** `fresh_food` 업종 팩, 전용 비전 프롬프트, 48시간 품질보상 정책(전액 30% / 부분 10% / 접수 2일)이 이미 코드에 있다. 없는 것은 라이브 검증·골든셋·실행 액션뿐이다.
- **전략 순서는 "신선식품 wedge → 뷰티 expansion"이다.** 신선식품은 사진 1장으로 환불/재배송을 끝내는 ROI가 가장 직접적이고, 가격 저항이 낮다(₩99k~₩199k). 뷰티는 성분 상담으로 카드 전환/객단가를 올리는 확장팩(₩199k~₩299k)이다.
- **상용화의 병목은 모델이 아니라 운영 계층이다.** 인박스, 액션(특히 재배송 생성), 분석, 배포, 콜드스타트, 지식 품질.
- **경쟁 전략은 명확하다.** "Cafe24 신선식품/뷰티 스토어를 위한, 상담→카드→주문→사진 클레임을 끝까지 처리하는 월 정액 AI CS 에이전트."
- **가격은 3~10배 저렴하게, 품질은 클레임 오탐 0과 카드 일치/환각 0으로 증명한다.** 이 조합이 ALF의 채널 장악과 Gorgias/Fin의 가격을 동시에 공격하는 유일한 길이다.
- **다음 14일은 "데모"를 "파일럿 가능한 제품"으로 바꾸는 데 쓴다.** 배포, 콜드스타트, 지식 재학습, 100문항 골든셋, 신선식품 18장 클레임 골든셋, 비밀키. 이 6개 없이는 어떤 벤치마킹도 의미가 없다.
