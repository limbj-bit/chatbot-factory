## 0. 한 장 요약

**우리는 이미 "Cafe24 뷰티 버티컬 AI CS 에이전트"라는 희소한 자산을 갖고 있다.**
성분·피부고민 기반 RAG, 상품 카드, Cafe24 OAuth 주문 조회, 사진 기반 클레임 판정, 환불 정책 엔진, AS 시나리오 상태머신이 한 코드베이스에 있다. 경쟁사(Channel Talk ALF, Gorgias, Intercom Fin, Zendesk, Tidio)는 모두 **수평형 helpdesk + AI agent**이며, 이 조합을 기본 제공하지 않는다.

**그러나 지금은 "상용"이 아니라 "데모에 가까운 상태"다.**
1. 최신 커밋 `639f482`가 라이브에 배포되지 않았다. `/health/ai`가 404다.
2. 사람 인계가 읽기 전용 알림 목록이라 실제 운영이 불가능하다.
3. 주문 조회 외에 취소·교환·환불 실행 액션이 없다.
4. 분석/QA/평가 지표가 없어 고객사가 ROI를 증명할 수 없다.
5. Render Free 콜드스타트(~50초)와 무료 LLM 의존이 "ChatGPT 수준" 약속을 깨뜨린다.
6. 라이브 카드 매칭에서 텍스트 추천과 카드 상품이 불일치하고, 카탈로그 근거 없는 상품명이 생성됐다(구버전 기준).

**전략은 하나다. 수평형 helpdesk와 정면 승부하지 말고, "뷰티 상담 → 상품 카드 → 주문 → 사진 클레임" 한 줄을 끝까지 자동화하는 버티컬 에이전트로 이긴다.**
가격은 경쟁사의 종량제(대화당 ₩500~2,900)를 따라가지 말고, **월 정액 ₩199k~₩299k + 공정사용**으로 3~10배 저렴하게 포지셔닝한다.

### 1.2 REA가 증명한 것

1. **고객 접점은 "서버 렌더링 HTML 1장 + 생성형 위젯 스크립트 1개"다.**
   SPA도, 번들러도, 클라이언트 라우터도 없다. 설치가 `<script src=".../api/widget/script?mall_id=...">` 한 줄이라는 뜻이며, 이는 중소 스토어 온보딩에서 강력한 장점이다.
2. **DOM이 113노드로 매우 가볍다.**
   초기 로딩과 TTFB에 유리하다. 반면 가상화 리스트, 복잡한 카드 인터랙션, 상태 관리가 없다는 뜻이기도 하다.
3. **정적 분석으로는 API 호출이 보이지 않는다.**
   위젯이 `config.apiBase + "/api/chat/stream"` 같은 **동적 문자열 조합**으로 호출하기 때문이다. REA가 endpoints 0개를 반환한 것은 "API가 없다"가 아니라 "정적 추출이 불가능하다"는 뜻이다.
4. **세션 지속은 localStorage 기반이다.**
   쿠키가 아니라 `claim_chat_session_{mallId}` 키를 첫 상호작용 때 만든다. 개인정보 측면에서는 가볍지만, 브라우저/기기 간 연속성은 없다.

### 1.3 REA가 못 본 것 (한계)

- 런타임 API 호출, 서버 내부, DB, LLM 라우팅은 REA의 정적 캡처 범위 밖이다.
- 따라서 아래 구조 분석은 **로컬 소스 검사 + 라이브 HTTP 프로브**로 보완했다.
- 개선 제안: 위젯에 **엔드포인트 상수 레지스트리**와 **source map**을 넣으면 REA/SAST/계약 테스트가 모두 쉬워진다. 지금은 85KB 생성 JS를 Python f-string으로 만들기 때문에 분석·디버깅·캐시 무효화가 어렵다.

- **텍스트 라우팅**: Groq Qwen3.8-27B → NVIDIA NIM → OpenRouter → Mistral → Gemini (마지막)

## 3. 라이브에서 확인된 운영/품질 리스크

### 3.1 배포가 최신이 아니다 (P0)

| 확인 | 결과 |
|---|---|
| `/health` | 200, `deploy_marker: schema-heal-v2` |
| `/health/ai` | **404** |
| 최신 커밋 | `639f482` (2026-11-05 push) |
| 결론 | `/health/ai`를 추가한 커밋이 라이브에 반영되지 않음 |

즉, 이번에 만든 속도 개선(실제 SSE, 8초 첫 토큰 타임아웃, 60초 쿨다운, RAG 다이어트)은 **아직 고객에게 제공되지 않고 있다.** Render 자동 배포가 꺼져 있거나, 빌드가 실패했거나, 다른 브랜치를 보고 있을 가능성이 있다.

### 3.2 상태 엔드포인트가 거짓말을 한다 (P0)

`/health`:
```json
{"status":"healthy","mock_ai":true,"mock_cafe24":true,"deploy_marker":"schema-heal-v2"}
```
- 실제 스트리밍은 LLM이 생성한 한국어 답변을 반환했다. `mock_ai: true`는 **설정값(`settings.MOCK_AI`)** 을 읽은 것이고, 실제 라우터의 유효 모드가 아니다.
- `mock_cafe24: true`도 실제 연동 상태와 무관하다.

`/api/system/schema-status`:
```json
{"ok":true,"stores_columns":null,
 "probe_error":"DBAPIError: ... current transaction is aborted ..."}
```
- `ok: true`인데 컬럼 목록은 `null`이다.
- PostgreSQL에서 한 문장이 실패하면 트랜잭션이 aborted 상태가 되고, 이후 조회가 모두 무시된다. 현재 코드는 `rollback()` 후 재시도하지만, **첫 실패 문장이 트랜잭션을 오염시킨 뒤**라 진단 자체가 신뢰할 수 없다.
- 상용 모니터링에서 이 엔드포인트를 health check로 쓰면 장애를 놓친다.

### 3.3 콜드스타트와 무료 LLM 의존 (P0)

- Render Free는 유휴 시 spin-down, 콜드스타트 ~50초.
- 고객이 광고를 보고 들어온 첫 50초를 기다리면 이탈한다.
- 무료 LLM 티어는 rate limit/품질 변동이 크다. Groq 1순위는 좋지만, 장애 시 NVIDIA/OpenRouter/Mistral/Gemini로 넘어가며 응답 시간이 출렁인다.
- 라이브 프로브 실측(구버전):

| 턴 | TTFT | 총 시간 | 카드 |
|---|---:|---:|---:|
| 지성·모공·피지 질문 | 1,332ms | 1,978ms | 0 |
| 동일 질문(새 세션) | 1,623ms | 2,039ms | 0 |
| 2턴 대화 1번째 | 7,483ms | 7,523ms | 0 |
| 2턴 대화 2번째 | 8,862ms | 8,902ms | 3 |

TTFT가 **1.3초~8.9초**로 6배 이상 출렁인다. 평균이 아니라 **꼬리 지연(tail latency)** 이 문제다. 8초 첫 토큰 타임아웃은 이 꼬리를 자르기 위한 것이므로, 배포되면 p95가 개선될 가능성이 높다.

### 3.4 카드/답변 접지 품질 (P0, 구버전 기준)

관측된 라이브 응답:
- 피부타입·고민·클렌저 선호를 모두 답한 턴에서도 카드가 **0개**.
- 2턴 대화에서 카드 3개가 붙었지만, 텍스트에서 추천한 "모공 클렌징 폼 / 차 트리 토너"와 카드 상품(`[특가판매] 루이셀 엔자임 파우더 [2+1]`, `필고마쥐 크림`, `[알뜰장터] 모이스처라이징 메이크업 리무버`)이 **불일치**.
- 카탈로그/카드 근거 없이 "루이셀 저자극 딥클렌징 폼", "루이셀 모공 케어 토너" 같은 상품명을 생성.
- 2번째 턴에서 직전 답변을 거의 반복.

이것은 모델 문제가 아니라 **검색→게이팅→카드 선택→프롬프트 접지**의 파이프라인 문제다. 새 커밋의 환각 금지/카드 게이팅이 이를 얼마나 고쳤는지는 **배포 후 동일 질문으로 재검증**해야 한다.

### 3.5 지식 데이터 품질 (P0)

- 라이브 지식 336건.
- 다수 가격이 `0원` 또는 `3,000원`(배송비 오인).
- 제목 "루이셀" 중복/쓰레기 문서 존재.
- 스토어 실제 상품은 482개 수준인데, sitemap 기반 수집은 169개에 그침.
- **지식이 틀리면 모델이 아무리 좋아도 답이 틀린다.** RAG 품질의 80%는 크롤링/정규화/가격 검증이다.

### 3.6 설정/보안 부채 (P0~P1)

- `render.yaml`은 SQLite, 라이브는 PostgreSQL → 대시보드 환경변수와 코드가 어긋날 위험.
- 관리자 기본 키 `admin-dev-secret-key-change-in-prod`가 프로덕션에서 변경되지 않았을 가능성.
- 채팅에 노출된 Neon 비밀번호, OpenRouter 키의 회전 미확인.
- 브랜딩 혼재: `/health` 서비스명 `Fresh Food Claim AI SaaS`, 스토어 `루이셀`, 제품 `챗봇공장`.
- 인증/감사 로그/테넌트 격리 수준이 ISMS-P 대응에 미달.

**우리의 구조적 강점 (경쟁사가 기본 제공하지 않는 것)**
1. **성분/피부고민 → 카테고리·성분 확장 검색**. "지성·모공"을 "퓨리파잉·BHA·세럼"으로 번역하는 도메인 사전은 수평형 봇에 없다.
2. **사진 클레임 판정**. 이미지 품질 검증 → 중복 해시 → 비전 관측 → 정책 임계값 → 환불 결정. 이건 CS 봇이 아니라 **보험 심사에 가까운 워크플로**다.
3. **Cafe24 네이티브**. OAuth, 토큰 암호화, 주문 캐시, rate limit, PII 제거. 글로벌 SaaS가 쉽게 복제하지 못하는 로컬 통합이다.
4. **1줄 설치 + 스토어별 페르소나/브랜딩**. 온보딩 마찰이 낮다.
5. **낮은 변동비 구조**. 5개 프로바이더 failover로 단가 협상력과 가격 여유가 있다.

**우리의 구조적 갭 (매출에 직접 타격)**
1. **사람 인계**: 읽기 전용 알림 목록. 답장/배정/상태/SLA 없음. → 상용 불가.
2. **실행 액션**: 주문 조회만. 취소/교환/환불/배송추적/쿠폰 없음. → "해결"이 아니라 "안내"만.
3. **분석/QA**: 해결률, 컨테인먼트, CSAT, 상담 품질, 지식 갭, 매출 기여 없음. → 고객사가 갱신 근거를 못 만든다.
4. **신뢰성**: 콜드스타트, 무료 LLM, SLA 없음, 최신 코드 미배포. → 계약서에 SLA를 못 쓴다.
5. **지식 품질/규모**: 336건, 가격 오류, 중복, 482개 상품 미수집, 렉시컬 검색. → 답변 품질의 상한이 낮다.
6. **채널/언어**: 웹 위젯만, 한국어만. → 카카오/네이버/인스타 유입을 못 받는다.
7. **인증/보안**: ISMS/ISO 없음, 비밀키 노출 이력. → 중견 브랜드 영업이 막힌다.

## 5. 벤치마킹 포인트: 무엇을 베끼고, 무엇을 피하고, 어디서 이길까

### 5.1 베낄 것 (Copy)

1. **Outcome/usage pricing의 투명성**
   - Fin: $0.99/outcome, ALF: ₩500~700/대화.
   - 우리도 "정액 + 초과분 단가"를 공개하라. 숨은 미터는 신뢰를 깎는다.

   - Fin Procedures, ALF 커맨드, Gorgias 주문 액션.
   - 우리는 "주문 조회 → 취소/교환/환불 → 배송 추적 → 쿠폰" 순으로 액션을 늘린다.
3. **사람 인계 + 문맥 전달**
   - 모든 경쟁사가 인박스/SLA/배정을 갖고 있다.
   - 우리는 최소 viable 인박스(스레드, 답장, 배정, 상태, SLA)를 P1에 넣는다.
4. **QA / 평가 / 시뮬레이션**
   - Fin은 배포 전 시뮬레이션/회귀 테스트를 제공한다.
   - 우리는 100개 골든셋 + CI 회귀 + "환각 0" 게이트를 만든다.
5. **지식 개선 루프**
   - ALF는 상담 데이터로 도큐먼트 개선을 제안하고, Fin Operator는 지식 최신화를 자동화한다.
   - 우리는 "답변 실패/지식 갭" 로그 → 크롤 재수집 → 문서 개선 제안으로 연결한다.
6. **채널 확장**
   - 한국은 카카오 상담톡/네이버 톡톡이 필수다. ALF가 이걸로 이긴다.
   - 웹 위젯만으로는 카페24 유입의 절반을 놓친다.
7. **신뢰**
   - ISMS/ISO, SLA, 데이터 보관/삭제 정책. 중견 브랜드 영업의 전제조건.

### 5.2 피할 것 (Avoid)

1. **Gorgias식 이중 미터(3rd-party 분석)**: AI 해결이 티켓으로도 과금되면 "해결할수록 비싸다"는 인식이 생긴다. 우리는 단일 미터로 간다.
2. **Zendesk식 좌석+AR 복잡도**: SMB는 계산을 못 한다. 정액제가 무기다.
3. **수평형 기능 팽창**: Intercom/ALF를 기능 수로 이길 수 없다. 뷰티/클레임/카페24에 집중한다.
4. **성공을 벌하는 종량제**: 자동화가 잘될수록 고객 비용이 늘면 갱신율이 떨어진다. 공정사용 + 상한선이 낫다.
5. **무료 티어 의존을 가격에 반영하지 않는 것**: 원가가 숨은 정액제는 규모가 커질 때 역마진이 된다.

### 5.3 이길 곳 (Win)

1. **뷰티 상담의 정확도**: 성분 근거, 피부고민 확장, 상품명 환각 0, 카드 일치율 90%+.

4. **가격**: 월 ₩199k~299k 정액. ALF/Gorgias/Fin 대비 3~10배 저렴.
5. **속도**: Groq 1순위 + 8초 컷. 단, 라이브 배포와 콜드스타트 제거가 전제.

## 8. 의사결정이 필요한 것

1. **인박스를 직접 만들 것인가, ALF/카카오에 인계할 것인가?**
   - 직접 만들면 데이터/UX 통제권이 생기지만 2~3주가 든다.
   - 연동하면 빨리 출시되지만 "AI가 해결하고 사람이 마무리"하는 경험이 분리된다.
   - 권고: **P1에서 lightweight 인박스 v1을 직접 만들고, 카카오/네이버는 어댑터로 붙인다.** 인박스는 CS SaaS의 심장이라 아웃소싱하면 락인이 약해진다.
2. **정액제 vs 종량제?**
   - 권고: **정액 + 공정사용 + 초과 단가**. 단, 원가 계측(토큰/프로바이더/대화)을 먼저 붙인다.
3. **무료 LLM을 계속 쓸 것인가?**
   - 파일럿까지는 가능. 유료 고객 계약에는 **SLA 가능한 프로바이더(유료 Groq/NVIDIA) + 폴백**을 명시해야 한다.
4. **뷰티 외 업종 확장 시점?**
   - 지금은 금지. 뷰티 10개 스토어에서 해결률/CSAT/원가를 증명한 뒤, 클레임이 유사한 식품/패션으로 확장한다.

## 9. 결론

- **구조적 자산은 충분하다.** 뷰티 도메인 RAG, Cafe24 주문, 사진 클레임, 정책 엔진, AS 상태머신은 수평형 경쟁사가 쉽게 복제하지 못한다.
- **상용화의 병목은 모델이 아니라 운영 계층이다.** 인박스, 액션, 분석, 배포, 콜드스타트, 지식 품질.
- **경쟁 전략은 명확하다.** "Cafe24 뷰티 스토어를 위한, 상담→카드→주문→클레임을 끝까지 처리하는 월 정액 AI CS 에이전트."
- **가격은 3~10배 저렴하게, 품질은 카드 일치/환각 0으로 증명한다.** 이 조합이 ALF의 채널 장악과 Gorgias/Fin의 가격을 동시에 공격하는 유일한 길이다.
- **다음 14일은 "데모"를 "파일럿 가능한 제품"으로 바꾸는 데 쓴다.** 배포, 콜드스타트, 지식 재학습, 골든셋, 비밀키. 이 5개 없이는 어떤 벤치마킹도 의미가 없다.
